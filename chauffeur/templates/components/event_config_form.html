{# ── An event's setup form: who rides, who drives, the time and place overrides, outside hands, optional / trip. ONE builder, two hosts: - the event modal's edit mode on the Schedule page (prefix `edit`, so its element ids are the `edit-*` ids the page always had), which saves one event at a time; - the Inbox dialog (prefix `triage`), which stages every event's answers and saves them together with one re-solve. Same concept, same builder (docs/ui_design_guide.md): before this file the form was hand-drawn once inside the modal, and a second consumer would have meant a second copy drifting from the first. The form only draws, fills and reads. Saving is the host's: it turns `eventConfigFormRead(p)` into requests with `eventConfigPayload(...)`, which is the one place that says what a save sends — so a staged inbox save and an immediate modal save cannot disagree about it. ctx: { passengers, drivers, driver_events?, assist_assignments? } — the schedule payload's own keys. `driver_events` is facet-gated and may be absent (scope.redact_schedule_blob removes it, never empties it). #}
