{# The admin surface's identity (auth arc S4). The dashboard and config page have never had one. That was defensible when they sat behind HA ingress; it stopped being defensible the day the app was published to the internet, and it is why /pin/clear could not be gated earlier — there was no token for the page to present. Three states, and the first-run one is the reason this is a component rather than a login box: * **claimed + signed in** — invisible, just a fetch wrapper attaching the token to every admin call. * **claimed + not signed in** — email and password. * **not claimed** — first run. Only offered when the request came through HA ingress, because that is proof Home Assistant already authenticated whoever is looking. Set a password for yourself and you are in; no mail round trip to yourself. Included by nav.html on every admin page (not a panel, not a kiosk), so none of them can drift apart — and so that, once enforcement is on, a page that is refused always has a way to sign in. #}
{# The token rides every same-origin request from this page. Installed unconditionally: it must be in place BEFORE any panel fetches, not after somebody signs in. The admin session has keys of its OWN. It used to share the PWA's `chauffeur_member_token`, and localStorage is per origin, so signing the PWA in as a child in one tab turned this page into the child's view in another: the schedule arrived redacted for a child and the drag-drop and triage editors broke on the missing keys. Signing in here wrote the PWA's identity the other way round. Neither side touches the other's keys now. #}
